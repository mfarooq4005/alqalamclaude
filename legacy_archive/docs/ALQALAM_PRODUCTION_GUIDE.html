Mobile App Mein Data Flow

1
App Start → Auth Check
App open hoti hai → expo-secure-store mein saved JWT token check hota hai → Agar token hai to seedha portal mein, warna login screen.
2
Login → PHP API Call
POST /auth/login → PHP backend username/password check karta hai → JWT token return karta hai → Token secure store mein save hota hai → Role ke hisaab se portal open hota hai.
3
Dashboard Data → TanStack Query
Har screen useQuery hook use karti hai → API call → Data cache hoti hai → 5 min tak same data dikhta hai (server hit nahi hota) → Pull-to-refresh se fresh data.
4
Real-Time Updates → Socket.io
Login ke baad SocketService.connect() → Node.js server se WebSocket connection → Staff check-in/out, fee collection, attendance updates — sab live dikhte hain.
5
Offline Mode → Mock Data Fallback
Agar API available nahi → try/catch mein mock data return hota hai → App kaam karti rehti hai → Green online indicator dikhta hai jab connection wapas aata hai.

📄 .htaccess — Security + Routing
Options -Indexes
ServerSignature Off

# ── Block .env from public access ──────────────────────────
<Files ".env">
    Require all denied
</Files>

RewriteEngine On
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

# ── CORS Headers ────────────────────────────────────────────
Header always set Access-Control-Allow-Origin "https://alqalam.edu.pk"
Header always set Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS"
Header always set Access-Control-Allow-Headers "Authorization, Content-Type"

# ── Security Headers ─────────────────────────────────────────
Header always set X-Content-Type-Options "nosniff"
Header always set X-Frame-Options "SAMEORIGIN"
Header always set X-XSS-Protection "1; mode=block"
🔒
Security: .env file ka permissions 600 set karo (File Manager → Right Click → Change Permissions → 600). Kabhi bhi .env ko git mein push mat karo.

Mobile App — Real API Se Connect Karo
Mock data hatao, real backend use karo
ℹ️
Abhi kya ho raha hai: Mobile app mein har screen try/catch use karti hai — API fail ho to mock data dikhata hai. Production mein API URL set karni hai.

Step 1: API URLs Update Karo

src/api/index.ts file mein ye 2 lines update karo:

📄 src/api/index.ts — URL Update
const API_URLS = {
  // PHP Backend (cPanel) — CRUD, login, fee, attendance
  php:  'https://alqalam.edu.pk/ems/alqalam_backend.php',

  // Node.js Backend (AWS EC2) — Real-time, socket.io
  node: 'https://api.alqalam.edu.pk',
};

Step 2: Environment Variables (Best Practice)

Project root mein .env file banao:

📄 alqalam_mobile/.env
EXPO_PUBLIC_PHP_API=https://alqalam.edu.pk/ems/alqalam_backend.php
EXPO_PUBLIC_NODE_API=https://api.alqalam.edu.pk
EXPO_PUBLIC_SCHOOL_NAME=AL Qalam International
EXPO_PUBLIC_VERSION=1.0.0

Phir src/api/index.ts mein use karo:

📄 src/api/index.ts — .env se read karo
const API_URLS = {
  php:  process.env.EXPO_PUBLIC_PHP_API  || 'http://192.168.1.100/ems/backend.php',
  node: process.env.EXPO_PUBLIC_NODE_API || 'http://192.168.1.100:3000',
};
✅
Expo Public Variables: EXPO_PUBLIC_ prefix wali variables app bundle mein include hoti hain. Secret values (API keys, passwords) kabhi EXPO_PUBLIC nahi rakhna — sirf backend server pe rakho.

Step 3: Production Mein Mock Data Remove Karo

Abhi ye pattern use ho raha hai:

Current Code (with fallback)
const { data = MOCK_STUDENTS } = useQuery({
  queryFn: async () => {
    try { return (await StudentsAPI.getAll()).data; }
    catch { return MOCK_STUDENTS; } // ← Offline fallback
  }
});

Ye production mein bhi kaam karta hai — API available hogi to real data, nahi hogi to demo data. Kuch change nahi karna padega!

💡
Agar sirf real data dikhana chahte ho (mock hata dena) to catch mein throw karo: catch(e) { throw e; } — TanStack Query error state dikhayega.

Over-The-Air (OTA) Updates

Aap koi bhi UI change, bug fix, ya new feature add karo → ek command run karo → Users ka app automatically update ho jaye. Play Store / App Store submission nahi karni. User ko kuch nahi karna padega.

✓ No Reinstall ✓ Instant Delivery ✓ Background Update ✓ Free Tier Available

Kya Update Ho Sakta Hai OTA?

✅ OTA Update Hoga
  • UI changes (colors, layout, text)
  • Bug fixes in TypeScript/JS code
  • New screens / features add karna
  • API URL changes
  • New components add karna
  • Business logic changes
  • Styles update karna
❌ New APK Chahiye
  • Native modules add karna (e.g., new camera)
  • app.json mein permissions change
  • Expo SDK version upgrade
  • New native dependencies
  • App icon / splash screen change
  • Bundle identifier change

User Ka Experience — Kya Hoga?

1
App Open Kare
User apna phone uthaye aur AL Qalam EMS app open kare.
2
Background Check (Automatic)
App startup par automatically Expo update server se check hota hai — koi naya update hai? (2-3 seconds, internet se)
3
Update Download
Update available hai → Background mein download hota hai (typically <1MB JS bundle) → User ko koi popup ya notification nahi dikhti.

Next Open → Updated Version
User agla baar app open kare to updated version automatically load hoga. Koi install nahi, koi prompt nahi.

Optional: Custom Update UI (Recommended)

Agar aap chahte ho ke user ko update dikhay, to app/_layout.tsx mein add karo:

📄 app/_layout.tsx — OTA Update Hook
import * as Updates from 'expo-updates';

export default function RootLayout() {
  useEffect(() => {
    async function checkForUpdates() {
      if (!Updates.isEnabled) return; // dev mode mein skip
      const update = await Updates.checkForUpdateAsync();
      if (update.isAvailable) {
        await Updates.fetchUpdateAsync();
        // Optional: user ko batao
        Alert.alert(
          'Update Available',
          'Naya version available hai. App restart karein?',
          [{
            text: 'Restart',
            onPress: () => Updates.reloadAsync()
          }, {
            text: 'Bad mein', style: 'cancel'
          }]
        );
      }
    }
    checkForUpdates();
  }, []);

  // ... rest of layout
}
